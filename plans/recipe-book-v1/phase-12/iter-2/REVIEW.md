## Миграция 20261021120000_reorder_categories.sql

- Образец проекта выдержан: `security invoker`, `set search_path = ''`, имена с схемой `public.`, `revoke execute ... from public, anon`, `grant execute ... to authenticated`. Новая таблица не создаётся, DELETE нет.
- `p_kind` выбирает таблицу ветвлением `if/elsif` с литералами, динамического SQL нет, поверхности инъекции нет; неизвестное значение — `raise exception 'unknown_category_kind'`.
- Пишется только `sort_order = ord * 10`. RLS-политика «authenticated full access» работает, потому что функция invoker. Триггеров на категориях нет, `updated_at` у них не существует.
- Один оператор `UPDATE ... FROM unnest(p_ids) WITH ORDINALITY`: одна транзакция, порядок не бывает переставлен наполовину. На `sort_order` нет unique (init.sql), промежуточных коллизий нет. Приведение bigint в integer при присваивании допустимо.
- Края: неизвестные id игнорируются без ошибки; дубль id даёт одну недетерминированную запись для строки (последствия безвредны); неполный список оставляет остальные строки со старым `sort_order`; `p_ids = null` — ноль строк. Клиент всегда отправляет полный список из кэша, так что все края практически недостижимы. Не блокирует.
