The selector argument correctly stays `({ l })`, but conventions → i18n is explicit that "the selector's result is bound to a single `const l`" for every component, precisely so i18n reads stay greppable as `l.xxx` everywhere. All four stub route files deviate from this in the same way (not a one-off typo), so it reads as an established-but-wrong local pattern that the next route file will copy. Straightforward fix: `const l = useI18nSelector(({ l }) => l.navigation); … <RouteStub title={l.<key>} />` (or keep the narrow single-key selection but still name it `l`).

- **`src/routeTree.gen.ts`** is currently untracked and not gitignored (consistent with `commit_policy: owner` — the developer never commits). The developer's choice to commit it (rather than gitignore) matches TanStack Router's own recommendation and is fine either way functionally, since `vite build` regenerates it fresh via the `tanstackRouter` plugin regardless of whether it was present in git before the build (verified: the plugin runs before `react()` and produces the file from `src/routes/**` alone). Flagging only so the owner knows this is a deliberate choice to review before the first commit, not an oversight — Cloudflare Pages will build correctly either way.
- **`getAuthSession()` (`src/hooks/useAuth.hook.ts:12-15`)** discards the `error` half of `supabase.auth.getSession()`'s result and treats any failure (expired refresh token, network hiccup during proactive refresh) as "no session" → redirect to `/login`. For this app's guard that's the correct fallback (there's no valid session to trust either way), so not filed as an issue, but it means a transient network failure while switching tabs silently looks identical to "logged out" with no diagnostic trace. Worth a `console.warn` if this ever needs debugging in the field — not blocking.
- **`__root.tsx`'s `RootComponent`** branches on `useRouterState({ select: pathname === "/login" })` to decide whether to wrap the outlet in `AppLayout`/`TabBar`, rather than the more idiomatic TanStack pattern of a pathless authenticated-layout route group with `/login` outside it. Works correctly and is small enough not to matter at this phase's scope (one root file, four tabs), but as more routes accumulate under the authenticated shell this inline branch is the one place that would need to grow — worth keeping in mind if the route tree gets deeper.
- Everything requiring a real Supabase account or a physical iPhone (session survives reload, login round-trip end-to-end, tab bar vs. real keyboard/home-indicator) is honestly left to the owner in the report rather than imitated — consistent with `visual_verification.enabled: false` and the phase's dependency on `B1`.
