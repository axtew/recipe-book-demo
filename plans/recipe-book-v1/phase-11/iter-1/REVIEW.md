## Issues

### Code issues

#### Types placement
- [code] `src/pages/LogPage/_internal/FinishSheet/_useFinishForm.ts:5` и `:11` — файл объявляет два типа (`interface IProps` и `type TFinishFields`) без соседнего `_types.ts`. Порог из конвенций (Placement, шаг 1 → 2): ≥2 объявлений — выносить. Завести `FinishSheet/_types.ts` (туда же можно перенести `IProps` из `_FinishSheet.tsx:11`, чтобы все локальные типы были в одном месте) либо оставить в файле один тип. Образец в этой же фазе: `src/components/CookLogSheet/_types.ts`.

#### Strong typing
- [code] `src/types/i18n.types.ts` (поле `cookLog.months: string[]`) и `src/pages/LogPage/_internal/MonthGroup/_MonthGroup.tsx:19` — `l.months[group.month - 1]` читает по вычисляемому индексу из `string[]`: тип не гарантирует ни длину 12, ни наличие элемента, при выпавшем элементе заголовок станет `undefined 2026`. Конвенции для ограниченного набора без enum требуют «plain object type with explicit keys». Либо кортеж из двенадцати `string` в `I18n`, либо объект с ключами по месяцам; решение «без `Date`/`Intl`» при этом сохраняется. В остальном словаре массивов нет, это единственное исключение из стиля.

#### DRY / single source of truth
- [code] `src/domain/schemas/_cookLogs.ts:53` (`max(99.99)`) и `src/components/CookLogSheet/_constants.ts:5` (`MULTIPLIER_MAX = 99.99`) — предел `numeric(4,2)` записан в двух местах, разойтись они могут молча. Источник должен быть один: константа рядом со схемой (экспортирована, и у неё есть импортёр — лист) либо предел только в схеме. Комментарии в обоих местах описывают одно и то же.

### Plan issues

#### Architectural placement
- [plan] Раздел «Файлы» плана помещает `CookLogSheet` в общий `src/components/`, хотя у листа один потребитель — `RecipePage/_internal/CookLogAction`. Конвенции (Placement, шаг 5): global — только когда потребители охватывают две или больше фичи или страницы; до этого — групповой корень или `_internal/` потребителя. Прецедент `ProductFormSheet` / `VariantFormSheet` в `src/components/` не подходит: у них несколько потребителей. План не называет причину, по которой место ближе не подошло. Решение за владельцем: принять как осознанное (если лист задуман ещё и для `/log` — дописать это в план одной строкой) либо перенести в `RecipePage/_internal/CookLogAction/_internal/`. Разработчик выполнил план буквально.

## Notes

**Проверено по просьбе владельца и признано нормальным**
- Зависимости: `package.json` получил только `@mantine/dates` и `dayjs`; в `pnpm-lock.yaml` добавлены ровно они (`clsx` уже был). У `@mantine/dates@9.5.2` peer `@mantine/core: 9.5.2` точно совпадает с установленным `core`; `9.7.x` потребовал бы обновить всё семейство. Рассинхрон `notifications@9.6.1` с `core` был до фазы и в неё не входит.
- `nutritionSnapshotSchema.parse` перед вставкой (`cookLogs.service.ts`): разумно. Интерфейс без индексной сигнатуры не присваивается `Json`, тип, выведенный из схемы, присваивается, и это заодно граница для `jsonb`-столбца, как требуют конвенции. Провал парсинга (`ZodError`) уходит из `mutationFn`, `mutateAsync` в `_useCookLogForm.ts:68` его ловит, форма показывает `submitError`, общий `MutationCache.onError` даёт уведомление, форма не запирается. Парсинг дублирует `safeParse` формы (там `snapshot` тоже проходит схему), но сервис — настоящая граница, дубль приемлем. Мелочь: невалидный снимок в форме дал бы «Проверьте дату и множитель», но при валидных рецептах это недостижимо (схема рецепта требует `amountGrams > 0` и целое положительное `servingsBase`).
- `prevValue: ""` для даты и множителя в `CookLogSheet` и `FinishSheet`: использует явный контракт `useForm` для формы создания со значением по умолчанию; `required` держит блок на пустом множителе; сброс идёт через `resetOn = isOpened`, а `getTodayDate()` вычисляется заново при каждом открытии, поэтому лист, оставленный открытым через полночь, не залипнет на вчерашней дате. После успешной отправки `prevValue` фиксируется и лист закрывается.
- Месяцы в словаре вместо `Intl`: соответствует правилу «весь видимый текст из словаря» и не требует `Date` для строки `YYYY-MM-DD`; замечание выше касается только типа.
- Инварианты: даты — строки, `getTodayDate` собирает местные части (не `toISOString`) и покрыт тестом около полуночи; `domain/stats` импортирует только тип `ICookLog`; сырая форма строки остаётся в сервисе; арифметики питательности вне `domain/nutrition` нет (`buildSnapshot` вызывается в хуке карточки поверх того же расчёта); удалений нет; `ICookLogInput` связан со схемой через `satisfies`.
- Экспорты: у каждого нового экспорта есть внешний импортёр (`COOK_LOGS_QUERY_KEY`, `formatMultiplier`, `getTodayDate`, `IMonthGroup`, мутации, `ICookLogInput` и др.); провизионных нет. Барели содержат только компоненты.
- Тексты: одна `l` на компонент, селектор `({ l })`, результат не деструктурируется; формулировки без рода («Записать готовку», «Доели», «Когда доели»). Единственный словарь `ru.json` обновлён.
- Комментарии: русские, без следов пайплайна. Слабое место одно — JSX-комментарий в `App.tsx` начинается с механизма, а не с назначения; не блокирую.

Те же `NumberInput size="md"` уже стоят в `VariantFormSheet` (прецедент до фазы), собственные кнопки и звёзды листа сделаны на 44px и больше.
