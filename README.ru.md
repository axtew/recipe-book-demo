# Recipe Book

> **Это публичная копия моего рабочего репозитория.** Рабочий закрыт: приложением я пользуюсь сам. Сюда копия синхронизируется вручную скриптом (`git filter-repo` и несколько проверок): рабочие заметки, учебные материалы и реквизиты деплоя в неё не попадают, поэтому хеши коммитов отличаются от закрытого репозитория. Интерфейс — на английском и русском (приложение следует языку браузера), у справочных документов есть английская и русская версии; журналы в `plans/` пока на русском.

Личное mobile-first PWA: справочник продуктов с КБЖУ, рецепты с автоматическим расчётом калорийности и БЖУ, поиск и журнал готовки.

## Что умеет

- **Продукты** с калориями, белками, жирами и углеводами на 100 г, несколько вариантов (марок) у продукта, один из них активный.
- **Рецепты:** ингредиенты в граммах, шаги, категории блюд, хранение, фото и ссылки на видео. КБЖУ считается на 100 г, на порцию и на всё блюдо.
- **Честный расчёт.** Продукт без КБЖУ никогда не считается нулём: рецепт сообщает, что расчёт неполный, и перечисляет такие продукты.
- **Поиск и фильтры** по рецептам и продуктам; весь набор данных живёт в клиенте, поэтому поиск мгновенный, а читать можно и без сети.
- **Журнал готовки** со снимком КБЖУ, оценкой, выходом и тем, на сколько хватило порции; в карточках рецептов — история и средние.
- Экспорт и импорт бэкапа в JSON; вместо удаления — архивирование.

Подробно — в [`docs/user-guide.ru.md`](docs/user-guide.ru.md).

## Как делалось

Архитектура, решения, планы, приёмка каждой фазы и ревью — мои. Код в основном пишут ИИ-агенты по пайплайну: **план → фаза (агент-разработчик) → статическое ревью (агент-ревьюер) → моё ревью → коммит мной**. Агенты не коммитят. Все их артефакты сохранены, чтобы процесс можно было проследить:

- [`docs/decisions/`](docs/decisions/README.md) — журнал архитектурных решений: стек, модель данных, границы продукта, отвергнутые варианты.
- [`plans/README.md`](plans/README.md) — как устроена разработка, а также планы, отчёты фаз и ревью каждой задачи (`plans/<задача>/`). Рабочие журналы ведутся на русском.
- [`AGENTS.md`](AGENTS.md) — карта и жёсткие инварианты, по которым работают агенты; конвенции, на которые она ссылается, лежат в [`docs/agents/`](docs/agents/conventions/).

Решения, на которые стоит посмотреть:

- Вся арифметика КБЖУ — в одном чистом модуле без импортов React и Supabase, округление только при отображении ([ADR 0017](docs/decisions/0017-nutrition-module-purity.md)).
- Удалений нет, только архивирование ([ADR 0014](docs/decisions/0014-archiving-instead-of-deletes.md)); записи журнала хранят снимок КБЖУ ([ADR 0018](docs/decisions/0018-cook-log-snapshot-and-dates.md)).
- Supabase без собственного серверного кода: доступ — грант плюс политика row level security ([ADR 0015](docs/decisions/0015-grant-plus-rls.md)); многошаговые записи — функции в базе через `rpc` ([ADR 0023](docs/decisions/0023-rpc-for-multi-step-writes.md)).
- Весь набор данных грузится в клиент и кэшируется в IndexedDB ([ADR 0012](docs/decisions/0012-whole-dataset-in-client.md), [ADR 0005](docs/decisions/0005-tanstack-query-persisted-cache.md)).

## Стек

React 19, TypeScript, Vite, PWA через `vite-plugin-pwa`; Mantine и styled-components; TanStack Query (с хранилищем в IndexedDB) и TanStack Router; zod; dnd-kit; Supabase (Postgres, Auth, Storage) без собственного серверного кода; Cloudflare Workers для статики; pnpm; ESLint, Prettier, Vitest.

## Запуск

Нужны Node.js (актуальный LTS), pnpm, Docker и Supabase CLI (он в devDependencies, запускается как `npx supabase`).

```bash
pnpm install
npx supabase start      # локальный Supabase, нужен запущенный Docker
pnpm dev                # дев-сервер против локальной базы (.env.development)
```

Тестовые данные и локальный дев-пользователь описаны в [`docs/agents/local-environment.md`](docs/agents/local-environment.md); скрипт дев-данных — `supabase/dev-data.sql`. Посмотреть демо-режим локально (плашка, готовый логин) — `pnpm dev:demo`.

| Команда           | Что делает                                                        |
| ----------------- | ----------------------------------------------------------------- |
| `pnpm dev`        | дев-сервер против локального стека Supabase                       |
| `pnpm dev:demo`   | то же в демо-режиме                                               |
| `pnpm build`      | прод-сборка (`vite build && tsc -b`), читает `.env.production`    |
| `pnpm build:demo` | демо-сборка, читает `.env.demo`                                   |
| `pnpm preview`    | просмотр собранного приложения                                    |
| `pnpm lint`       | ESLint                                                            |
| `pnpm test`       | Vitest                                                            |
| `pnpm db:reset`   | пересоздать локальную базу из миграций и seed                     |
| `pnpm db:types`   | перегенерировать `src/types/database.types.ts` из локальной схемы |

## Тесты

`pnpm test` запускает Vitest. Модуль расчёта КБЖУ тестируется в обычном Node без DOM; эталон демо-данных (`supabase/demo/seed.json`) сверяется со схемой бэкапа, ссылочной целостностью и расчётом самого модуля.

## Развернуть у себя

1. Создайте проект Supabase, **выключите регистрацию** (Authentication → Sign In / Providers → User Signups) и заведите пользователя вручную: политики базы дают любому вошедшему доступ ко всем данным.
2. Привяжите CLI и накатите миграции: `npx supabase link --project-ref <ref>`, затем `npx supabase db push`.
3. Скопируйте [`.env.example`](.env.example) в `.env.production` и подставьте адрес проекта и publishable key. В сборку попадает только publishable key; ключ secret и пароль базы — никогда.
4. `pnpm build`, затем выложите `dist/`. В репозитории есть конфиг Cloudflare Workers для статики (`wrangler.jsonc`): `npx wrangler deploy`.

Полноценный стенд вроде живого демо (отдельный проект, общий логин, ночной сброс, пинг против засыпания бесплатного тарифа) расписан по шагам в [`supabase/demo/DEPLOY.ru.md`](supabase/demo/DEPLOY.ru.md).

## Известные ограничения

- Рассчитано на двоих пользователей и телефоны, iOS в приоритете; десктопный вид — одна колонка по центру.
- Запись требует сети; без неё ранее загруженные данные можно только читать.
- Весь набор данных грузится при запуске: ни серверного поиска, ни пагинации, ни фильтрации в базе — так задумано при таком объёме данных.
- Аккаунты заводятся вручную: регистрации, ролей и общего доступа между домохозяйствами нет.
- Демо-контент только на английском, какой бы язык интерфейса ни был выбран.
