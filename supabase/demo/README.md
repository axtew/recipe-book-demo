# Демо-данные

Эталон для демо-проекта: 20 выдуманных рецептов с фото (два из них — по видео), 65 продуктов (75 вариантов), журнал готовки на 39 записей. Это файл бэкапа версии 1 — его принимает импорт на экране настроек и функция сброса демо.

## Что где лежит

| Путь                           | Что                                                                                                         |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `source/products.ts`           | категории продуктов, продукты, варианты и КБЖУ на 100 г                                                     |
| `source/recipes.ts`            | рецепты: состав в граммах, шаги, категории блюд, хранение, заметки, поля `photo` и `videoUrls`              |
| `source/cookLogs.ts`           | журнал готовки                                                                                              |
| `source/_types.ts`             | формы исходников                                                                                            |
| `_build.ts`                    | генератор: раздаёт `id`, связывает строки по названиям, считает снимки КБЖУ модулем `src/domain/nutrition/` |
| `seed.json`                    | результат генератора; руками не правится                                                                    |
| `__tests__/seed.test.ts`       | сверка `seed.json` с исходниками, схема бэкапа, ссылочная целостность, снимки журнала                       |
| `photos/`, `photos/CREDITS.md` | фото рецептов (WebP, как их сохраняет приложение) и их источники                                            |

## Как пересобрать `seed.json`

Генератор написан на TypeScript и запускается тестовым прогоном vitest: он понимает алиас `@/` и тянет доменный модуль, а отдельного рантайма TS в репозитории нет. Правка исходников без пересборки роняет тест `совпадает с тем, что собирает генератор`.

PowerShell:

```powershell
$env:WRITE_DEMO_SEED = "1"; pnpm vitest run supabase/demo; Remove-Item Env:WRITE_DEMO_SEED
```

bash:

```bash
WRITE_DEMO_SEED=1 pnpm vitest run supabase/demo
```

## Правила данных

- Идентификаторы детерминированы: `de0000KK-0000-4000-8000-NNNNNNNNNNNN`, где `KK` — вид строки (01 категория продуктов, 02 категория блюд, 03 продукт, 04 вариант, 05 рецепт, 06 шаг, 07 ингредиент, 08 запись журнала). Повторная сборка даёт тот же файл.
- Цифры КБЖУ — по общеизвестным таблицам питательности. Крупы и макароны указаны для сухого продукта, мясо и рыба — для сырого.
- Единственный продукт без КБЖУ — «Аджика домашняя» (рецепт «Чили кон карне» показывает предупреждение о неполном расчёте). Единственный архивный продукт — «Сметана 15%», она остаётся в старой «Творожной запеканке».
- Снимки журнала считаются от базового числа порций рецепта, как в карточке рецепта в приложении; множитель хранится отдельно.
- Фото рецепта: имя файла из `photos/` в поле `photo`. В `seed.json` оно превращается в `photo_path` вида `<id рецепта>/cover.webp` — ровно тот путь, который приложение пишет при загрузке обложки (`uploadRecipePhoto`). Сами файлы в `seed.json` не входят: их кладёт в Storage сценарий настройки демо.
- Видео: поле `videoUrls` попадает в `video_urls`. Рецепты «Овсяное печенье» и «Блины» пересказаны по роликам своими словами; количества «Блинов» пересчитаны из стаканов и ложек в граммы, это сказано в заметке рецепта.
- Файл `seed.json` помечен в `.gitattributes` как `eol=lf`: он уходит в `jsonb`, а тест сверяет его с генератором.
- Типы папки проверяет `tsc -b` (проект `tsconfig.demo.json`, входит в `pnpm build`).

## Куда сценарию настройки демо (P4) загружать фото

Бакет `recipe-photos`, путь объекта `<id рецепта>/cover.webp`, `contentType: image/webp`, `upsert: true`. Идентификатор рецепта берётся из `seed.json` по названию (поиск по `recipes[].name`), файл — из таблицы ниже. Загрузку выполнять до или после импорта `seed.json` — порядок не важен, публичная ссылка строится по пути.
