# 0027. Внешние источники КБЖУ отвергнуты; замена — этикетка по фото через облачный vision-API

- Статус: принято (реализация — Фаза 13 плана, отложена, приоритет низкий)
- Дата: 2026-08-02

## Контекст и проблема

Хотелось не вводить КБЖУ новых продуктов руками, а брать их из внешней базы по штрихкоду. Тема закрыта по результатам проверки 2026-08-02; записана как отрицательный результат эксперимента, чтобы к ней не возвращаться.

## Рассмотренные варианты

1. **Open Food Facts** — отвергнут по результатам проверки. Пробили реальные упаковки из дома в Дананге: больше половины не нашлось вообще, а у почти всего найденного не заполнены `nutriments`. Полные данные оказались ровно у двух позиций — Choco Pie и одно печенье, то есть у международных брендов. Для вьетнамской продуктовой корзины база пустая. Пересматривать имеет смысл только если OFF заметно нарастит покрытие по ЮВА — само по себе это не произойдёт.
2. **FatSecret** — отвергнут ещё до проверки: OAuth 2.0 client credentials → секрет нельзя держать в браузере; на бесплатном тарифе нужен whitelist по IP, а у serverless-функций исходящий IP плавает, то есть «free tier + Edge Function» не заводится; плюс ограничения на коммерческое использование.
3. **USDA FoodData Central** — отвергнут: только английский и только американские продукты. Матчинг «сметана 20%» → `Sour cream` без модели ненадёжен, а с моделью проще сразу читать этикетку.
4. **Штрихкодные базы** — с приличным покрытием Вьетнама не существует. Общие каталоги товаров (UPCitemdb и подобные) не содержат КБЖУ, GS1 — это реестр регистраций, не пищевая ценность. Таблицы вьетнамского Института питания описывают обобщённые продукты, а не марки в упаковке.
5. **Распознавание таблицы пищевой ценности по фото этикетки** — не зависит ни от какой чужой базы, покрывает товары без штрихкода (развес, рынок, переупаковка) и любые языки этикетки.

Vision: облачный API против локальной модели.

## Решение

- **Замена — распознавание таблицы пищевой ценности по фото этикетки** (Фаза 13 плана).
- **Vision — облачный API, а не локальная модель.** Несколько десятков снимков в месяц стоят центы, работает всегда и откуда угодно, не требует ни туннеля, ни бодрствующего ноутбука. Ключ живёт в Supabase Edge Function.
- **Полей `barcode` / `external_id` в схеме нет.** Заводились под сканер, источника не будет — поле без источника это мёртвый груз. `source` остаётся в виде `seed | manual | label | llm` ([ADR 0016](0016-variants-and-active-variant.md)).
- **Критическое требование к распознаванию: различать «на 100 г» и «на порцию».** На азиатских упаковках порционная подача частая, и молча принять её за стограммовую — это тихо неверные цифры во всех рецептах с этим продуктом.
- **Приоритет фазы — низкий.** Четыре числа с этикетки набираются за ~20 секунд, новые продукты после первого месяца редки. Делать, только если ручной ввод реально начнёт раздражать.

## Последствия

- Это снимает необходимость домашнего хостинга для данной фичи целиком ([ADR 0013](0013-cloudflare-hosting.md)). Локальная модель остаётся уместной только для будущего ассистента планирования ([ADR 0028](0028-local-llm-assistant-deferred.md)), и то по желанию, а не по нужде.
- Камерная фича обязана работать в Safari на iOS, в том числе из PWA на домашнем экране ([ADR 0001](0001-personal-app-for-two.md)).
