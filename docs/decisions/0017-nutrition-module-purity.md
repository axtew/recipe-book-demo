# 0017. Расчёт КБЖУ — изолированный чистый модуль, без молчаливых нулей

- Статус: принято
- Дата: 2026-08-02

## Контекст и проблема

Расчёт КБЖУ и масштабирование — сердце приложения. Нужно, чтобы цифры были проверяемы тестами, модуль можно было переиспользовать (в том числе серверным кодом и будущим LLM-сервисом), а неверные числа не маскировались нулями. Модели галлюцинируют числа, а неверные цифры хуже отсутствующих.

## Рассмотренные варианты

1. **Изолированный модуль чистых функций без React.**
2. Расчёт в компонентах и хуках по месту.
3. Расчёт силами LLM — отвергнуто: LLM делает извлечение и сопоставление (распарсить рецепт, сматчить продукт на справочник, предложить КБЖУ нового продукта), детерминированный TS-модуль делает всю арифметику ([ADR 0028](0028-local-llm-assistant-deferred.md)).

## Решение

- Расчёт КБЖУ и масштабирование — **изолированный модуль чистых функций без React**, чтобы его мог импортировать серверный код (в т.ч. будущий LLM-сервис). Он живёт в `src/domain/nutrition/`, не импортирует React, Supabase и Mantine и запускается в Node без DOM.
- **Округление только в UI** (ккал целые, БЖУ один знак), домен оперирует сырыми числами.
- **Молчаливых нулей не бывает:** при незаполненном КБЖУ у продукта — явное предупреждение со списком проблемных продуктов, а не молчаливые нули. Продукт без КБЖУ даёт запись в `incompleteProducts`.
- Опциональные ингредиенты (`is_optional`) в расчёт КБЖУ не входят.
- Внутренние типы модуля остаются в `src/domain/nutrition/_types.ts`: за пределами модуля они почти не нужны.

## Последствия

- Ни один компонент, хук или сервис не считает питательность сам — [`conventions/data.md`](../agents/conventions/data.md) → «Чистота доменного модуля».
- Модуль покрывается тестами до всякого интерфейса ([`conventions/testing.md`](../agents/conventions/testing.md)).
- Смысл расчёта для рецепта — [`architecture.md`](../agents/architecture.md).
