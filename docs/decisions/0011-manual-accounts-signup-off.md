# 0011. Аккаунты заводятся вручную, регистрация выключена

- Статус: принято
- Дата: 2026-08-02

## Контекст и проблема

Приложение личное, на двоих ([ADR 0001](0001-personal-app-for-two.md)). Нужна авторизация без экрана регистрации и без лишних слоёв защиты.

## Рассмотренные варианты

1. **Аккаунты вручную в дашборде Supabase, RLS «только authenticated».**
2. PIN поверх логина — не делаем: телефон под блокировкой.
3. Открытая регистрация — нельзя, пока политики RLS выглядят как `using (true) to authenticated` ([ADR 0029](0029-multi-tenancy-deferred.md)).

## Решение

**Auth** — аккаунты заводятся вручную в дашборде Supabase. UI регистрации нет. RLS-политики «только authenticated». PIN поверх не делаем.

**Регистрацию новых пользователей обязательно выключить в настройках проекта** (Authentication → Providers → Email). RLS даёт доступ роли `authenticated` целиком, без разбора по владельцу — при открытой регистрации любой, кто узнал URL проекта, заводит аккаунт и получает всю базу. Это единственная реальная дыра в такой схеме безопасности, и закрывается она одним переключателем.

## Последствия

- **Publishable key** (`sb_publishable_...`) в клиентском бандле — это нормально, он для этого и предназначен, данные защищает RLS. **Secret key** (`sb_secret_...`) в клиент попадать не должен никогда — он обходит RLS.
- Ключи Supabase переименованы: `sb_publishable_*` вместо прежнего `anon`, `sb_secret_*` вместо `service_role`. Старые имена встречаются в документации и статьях — это то же самое по назначению. Переменная окружения в проекте называется `VITE_SUPABASE_PUBLISHABLE_KEY`.
- Настоящие секреты проекта, которым место в менеджере паролей: **Database Password** и **secret key**. Project URL и publishable key секретами не являются.
