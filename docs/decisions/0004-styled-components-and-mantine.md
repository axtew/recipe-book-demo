# 0004. styled-components для своей вёрстки, Mantine для тяжёлых компонентов

- Статус: принято
- Дата: 2026-08-02

## Контекст и проблема

Нужен способ писать стили и готовый набор UI-компонентов. Критерии: функционал важнее, ресурсы не тратим; дизайн сам делать не хочу, поэтому headless-библиотека (где рисуешь все пиксели сам) — прямо противоположный выбор.

## Рассмотренные варианты

Стили:
1. **styled-components** — решающий аргумент: привычка и скорость разработки.
2. Tailwind — разница в производительности на этом объёме данных не заметна, перформанс аргументом не был.
3. Zero-runtime (Linaria / vanilla-extract / Panda CSS) — на случай, если когда-нибудь понадобится та же эргономика без рантайма.

UI kit:
1. **Mantine** (актуальная мажорная версия — 9.x).
2. Radix — отвергнут: ноль визуала, нет Combobox, DatePicker, Rating, NumberInput.
3. Radix Themes — визуал есть, но набор компонентов беднее: те же три дорогих компонента писать самому.

## Решение

**styled-components** для стилей: свои экраны и вёрстка. **Mantine** — для тяжёлых компонентов: Combobox с поиском, Drawer снизу, DatePicker, Rating, NumberInput, Dropzone, Notifications, Skeleton — самых дорогих в самостоятельной реализации.

## Последствия

- Риск принят: styled-components с 2025 официально в maintenance mode (только фиксы совместимости, новых фич нет). С React 19 работает. Если понадобится zero-runtime с той же эргономикой — Linaria / vanilla-extract / Panda CSS (идея в [`BACKLOG.md`](../../BACKLOG.md)).
- Со styled-components Mantine не конфликтует: с 7-й версии он на CSS-модулях и CSS-переменных.
- Правила применения — [`conventions/styling.md`](../agents/conventions/styling.md).
